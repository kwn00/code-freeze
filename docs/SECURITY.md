# 보안 설계 (치트 방지와 위협 모델)

원칙: **서버 권위.** 클라이언트는 "의도"(이 칸에 이 타워를 지어 줘, 웨이브 시작해 줘, 빠르기 ×2)만 보낸다.
돈(SP)·가용성·버그의 위치와 체력·피해·웨이브 진행·결과·순위는 모두 서버가 `packages/shared/src/sim.ts` 로 계산한다.
화면은 서버가 보낸 상태를 그리기만 한다. 화면 코드를 고쳐도 바뀌는 것은 자기 화면에 보이는 것뿐이다.

## 위협과 대응

| 위협 | 대응 | 어디 |
| --- | --- | --- |
| 돈·가용성·점수 바꾸기 | 그런 값을 보내는 메시지가 **없다**. 받는 메시지는 `hello · build · upgrade · sell · wave · speed · pause · restart · ping` 뿐이고, 모양·범위를 확인한 것만 쓴다 (모르는 키는 버린다: 예를 들어 `build` 에 `cost` 를 붙여도 값은 서버의 표대로 받는다) | `protocol.ts` `parseClientMsg` |
| 길 위·남의 칸·맵 밖에 짓기, 돈 없이 짓기·올리기, 해금 전 타워 짓기 | 서버가 `canBuildAt`, 돈, 단계 상한, 해금 스프린트(`isUnlocked`)를 다시 확인하고 맞지 않으면 무시한다. 화면의 🔒 표시는 안내일 뿐이다 | `sim.ts` `build`·`upgrade`·`sell`·`isUnlocked` |
| 시간 앞당기기 (빨리 감기 핵) | 시간은 서버 틱(30Hz)으로만 흐른다. 빠르기는 1·2·3 중 하나만 받아, 서버 1초에 sim 은 최대 3초 흐른다. 리더보드는 서버 시간보다 3배 넘게 빠른 판을 다시 한 번 버린다 | `game.ts` `tick`, `leaderboard.ts` `record` |
| 팔기 값 부풀리기 | 돌려받는 값은 서버가 타워마다 센 "이번 짓는 시간에 쓴 값"(원가로 돌려받음)과 그 전에 쓴 값(70%)으로 계산한다. 이 값은 웨이브가 시작될 때 서버가 0 으로 만들고, 웨이브 중에 쓴 값은 들어가지 않는다. 짓기·팔기를 되풀이해도 돈은 늘지 않는다 (원가로 돌려받을 뿐). 화면에 보내는 이 값은 버튼 문구용이다 | `sim.ts` `sellValue`·`startWave` |
| 멈춘 채로 웨이브 시작·짓기로 이득 보기 | 멈춘 동안 웨이브를 시작할 수 없다. 짓기·올리기·팔기는 짓는 중·웨이브 중·멈춤 모두 같은 규칙이고(타워디펜스의 보통 규칙), 멈춘 동안 시간이 흐르지 않으므로 시간을 버는 일은 없다 | `game.ts` `handle` |
| 점수 위조 | 기록은 판이 끝날 때 서버가 직접 쓴다. 점수를 제출하는 요청이 **존재하지 않는다** (`/api/leaderboard` 는 읽기 전용). 한 판에 한 번만 남기고, 저장할 때와 DB 에서 읽을 때 모양(이름, 범위, 프리즈 성공이면 스프린트를 충분히 막았는지(0.1.x 의 10, 지금은 30 이상이면 반드시 성공), 끝날 때의 타워 목록이 아는 종류·단계인지)을 다시 확인한다. 화면도 받은 순위표의 모양을 확인하고 이름은 `textContent` 로만 넣는다 | `game.ts` `finish`, `leaderboard.ts` `isValidEntry` |
| 퇴근·다시 시작으로 기록 고르기 | 퇴근(`retire`)은 값이 없는 메시지이고, 막은 스프린트는 서버가 센다 (웨이브 중이면 그 웨이브는 빼고). 다시 시작하거나 판이 닫히거나(오래 끊김·무응답) 서버가 꺼질 때도 그때까지 막은 스프린트로 기록한다. 한 판에 기록은 하나뿐이고, 기록이 남는 것은 순위가 내려가는 쪽으로만 작용한다 (나쁜 판을 지울 수는 없다: 순위표는 판마다 남기고 가장 좋은 판이 위에 온다) | `game.ts` `finish`, `sim.ts` `retire`·`clearedOf` |
| 야근으로 서버 계산량·전송량 늘리기 | 맵의 버그는 400마리까지만 (넘치면 더 나오지 않는다). 빈칸을 모두 4단계 타워로 채운 최악의 판도 틱 평균 0.1ms 안쪽 (측정). 상태는 웨이브 중 초당 10번, 버그 체력은 비율(1~100)만, 타워 목록은 바뀔 때만, 효과 좌표는 소수 둘째 자리까지 보낸다 (최악의 판 한 사람 평균 약 4KB/s, 측정) | `sim.ts` `MAX_ENEMIES`, `protocol.ts` `snapshotOf`, `game.ts` `flush` |
| 공개 API 로 DB 두드리기 (시즌) | 지금 시즌은 메모리에서 답하고 DB 를 기다리지 않는다. 시즌 목록은 1분 동안 들고 한 번에 하나만 읽으며, 실패하면 30초 동안 다시 묻지 않는다. 지난 시즌은 있는 시즌일 때만(없으면 404, 숫자가 아니면 400, 목록을 못 읽으면 503) 저장소에서 읽어 10분 동안 들고 있고, 같은 것을 동시에 물어도 한 번만 읽는다. 읽은 기록도 모양을 확인하고 내보낸다. 모든 GET 은 IP 당 제한을 받는다 | `leaderboard.ts` `seasons`·`pastTop`, `index.ts` |
| 순위표 도배 | 스프린트를 하나 이상 막은 판만 남는다. 스프린트를 막으려면 서버 시간으로 실제로 버텨야 한다. 판 수는 세션 발급(IP 당 초당 0.5개)·연결 수(IP 당 4) 제한에 묶인다 | `leaderboard.ts`, `index.ts` |
| 이름에 스크립트·보이지 않는 글자 넣기 | 서버가 NFKC 정규화 뒤 글자·숫자·일부 기호만 남기고 12자로 자른다. 화면은 `textContent` 만 쓰고, 서버에서 온 이름도 다시 확인한다. CSP 로 인라인 스크립트를 막는다 | `names.ts`, `main.ts`, `security.ts` `SECURITY_HEADERS` |
| 서버가 보낸 값 믿기 (중간자·서버 오류) | 화면은 서버 상태의 모양·범위를 확인한 것만 그린다 | `view.ts` `checkSnapshot` |
| 남의 판 이어받기 | 판마다 운영체제 CSPRNG 로 만든 192비트 이어받기 키가 있고, 그 판의 브라우저 탭(sessionStorage)에만 준다. 틀린 시도도 1회용 세션 토큰을 쓰므로 대입은 세션 발급 제한에 묶인다 | `game.ts` `resumeKey`, `index.ts` |
| 한 판을 두 연결로 쓰기 | 이어받으면 옛 연결을 닫는다 (4009) | `index.ts` |
| 세션 토큰 위조·재사용 | HMAC-SHA256 서명 (`SESSION_SECRET`, 프로덕션에서 없으면 기동 거부), 10분 만료, 한 번만 쓸 수 있다. 비교는 시간이 일정한 비교 | `security.ts` |
| 다른 사이트에서 연결 (CSWSH) | WebSocket 과 세션 발급은 같은 출처(또는 `ALLOWED_ORIGINS`)만 받는다 | `security.ts` `originAllowed` |
| 메시지 홍수·큰 메시지 | 연결마다 토큰 버킷(초당 15, 한 번에 30). 계속 넘치면 끊는다 (4029). 메시지는 256바이트까지 (넘으면 1009). 모양이 틀린 메시지 5번이면 끊는다. hello 는 5초 안에 | `index.ts`, `constants.ts` |
| 서버 메모리 붙잡기 (판을 열고 버티기) | 동시 판 300개, 연결 400개, IP 당 연결 4개, IP 당 연결 없이 지켜 두는 판 3개(넘치면 오래된 것부터 닫는다). 15분 동안 아무 메시지가 없으면 닫고, 끊긴 판은 10분 뒤 닫는다 | `index.ts`, `game.ts` `expired` |
| 끊어서 피해 피하기 | 끊기면 판이 멈춘다. 멈춤은 원래 언제든 할 수 있으므로 얻는 것이 없다. 다시 붙으면 멈춤 상태로 돌아온다 | `game.ts` `detach`·`attach` |
| 클라이언트 IP 위조로 제한 피하기 | Render 앞단(Cloudflare)이 덮어쓰는 `cf-connecting-ip` 만 믿는다. X-Forwarded-For 맨 앞 값은 쓰지 않는다 | `security.ts` `clientIp` |
| 경로 탈출로 서버 파일 읽기 | 정규화 뒤 `apps/client/dist` 밖이면 403. 화면 파일이 아니면 index.html | `index.ts` `serveStatic` |
| 한 판의 오류로 서버 전체 멈추기 | 틱마다 판별로 오류를 잡아 그 판만 닫는다. 요청 처리 오류도 잡아 500 으로 답한다 | `game.ts` `GameManager`, `index.ts` |
| DB 를 통한 공격 / 장애 전파 | 파라미터 쿼리만 쓴다. 순위는 메모리에서 답하고 저장은 뒤에서 재시도하므로 DB 가 느리거나 죽어도 게임과 조회는 멈추지 않는다. TLS 인증서 검증을 끄지 않는다 | `leaderboard.ts`, `store-postgres.ts` |
| 리더보드 기록 유실 | 기록은 지우지 않는다 (DELETE·TRUNCATE·DROP 을 쓰지 않는다). 종료 신호(SIGTERM)를 node 가 직접 받아 남은 기록을 마저 쓴다 | `store-postgres.ts`, `index.ts` `shutdown`, `render.yaml` |

## 남는 위험 (서버 권위로도 막을 수 없는 것)

- **자동 입력(봇)**: 사람 대신 프로그램이 짓기·웨이브를 누르는 것. 판정은 모두 서버가 하므로 봇이 할 수 있는 것은 사람이 할 수 있는 것과 같다 (더 빠르게 누를 뿐이고, 타워디펜스는 누르는 속도가 점수를 크게 바꾸지 않는다).
- **화면 바꾸기**: 자기 화면의 그림·숫자를 바꾸는 것. 서버의 상태와 순위에는 영향이 없다.
