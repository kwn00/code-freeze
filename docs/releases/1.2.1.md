# v1.2.1

## 달라진 점

- **순위표에 클리어 시간.** 줄마다 `⏱ 12:34` 처럼 클리어 시간이 나옵니다. 1시간이 넘으면 `1:02:05`.
  - 클리어 시간은 **게임 안 시간**입니다: 막은 스프린트까지 웨이브가 돈 시간의 합. 빠르기(×1~×5)를 올려도, 짓는 중이거나 멈춰 둔 시간이 길어도 똑같이 셉니다 (빠르기를 올린 사람이 저절로 위로 가지 않게). 버그를 빨리 잡을수록 웨이브가 빨리 끝나서 짧아집니다.
  - 웨이브 중에 끝난 판(장애, 퇴근, 닫힘)은 그 웨이브가 시작될 때까지의 시간입니다 (잡은 버그 수와 같은 규칙).
- **같은 점수면 클리어 시간순.** 순위: 막은 스프린트 → 남은 가용성 → **클리어 시간(짧을수록 위)** → 잡은 버그 → 먼저 세운 기록. 예전에는 가용성 다음이 잡은 버그였습니다.
  - 1.2.1 전의 기록에는 클리어 시간이 없어서 `⏱ —` 로 나오고, 같은 점수 안에서는 시간이 있는 기록 뒤에 섭니다.

## 내부 변경

- `sim.ts`: `timeAtWaveStart`, `recordedTime` (퇴근하면 `time` 도 그 값으로). `game.ts`: 결과에 `time`(정수 초).
- 순위표 응답의 줄에 `time` 을 더했습니다 (없는 기록은 빠짐). 서버와 화면이 범위(0초~10일, 정수)를 확인합니다.
- DB: `runs` 표에 `play_seconds integer` 열을 `ALTER TABLE … ADD COLUMN IF NOT EXISTS` 로 더합니다. 예전 기록은 NULL 로 그대로 두고 지운 기록은 없습니다. 정렬은 `play_seconds ASC NULLS LAST` (`compareRuns` 와 같은 순서).
- 리더보드 시즌(1)과 통신 규격은 그대로입니다.

## 확인한 것

- 타입 검사, 클라이언트 빌드, 단위 테스트 76개 통과 (PostgreSQL 테스트는 로컬 PostgreSQL 16). 새 테스트: 정렬(스프린트 → 가용성 → 시간 → 시간 없는 예전 기록), 이상한 시간 거절, 웨이브 중에 끝난 판의 시간, 1.2.0 모양의 표(예전 기록이 든 채)에 열을 더하고 정렬하기, 시간 표시(`m:ss`, `h:mm:ss`).
- 로컬 PostgreSQL 에 붙인 실제 서버에 브라우저(Chromium, iPhone 13 · 320×568)로: 판을 끝내 순위표에 `⏱ 0:14` 가 나오고 예전 기록은 `⏱ —` 인 것, DB 에 `play_seconds` 가 들어가고 예전 행은 그대로인 것을 봤습니다. 가로 스크롤과 콘솔 오류가 없습니다.
